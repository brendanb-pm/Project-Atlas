# Ricardo Usability Test Plan

## Purpose

Observe a future IPM owner/operator pilot without expecting systems, server, spreadsheet, or ERP-administration skills.

## Tasks

1. Add a customer.
2. Create or receive an RFQ.
3. Prepare a quote.
4. Convert accepted work to a Job.
5. Find current workload.
6. Change work status.
7. Record a manufacturing/process observation.
8. Find that information later.
9. Invoice completed work.

For each, record completed-without-help, elapsed time, wrong turns, questions, terminology confusion, missing capability, UX issue, configuration issue, and bug. Do not coach unless the participant is blocked; record the intervention before helping.

## Assistance Events metric

Each time Ricardo needs Brendan’s help, add one `ASSISTANCE EVENT` classified as `TRAINING`, `UX`, `BUG`, `MISSING_CAPABILITY`, `CONFIGURATION`, or `TECHNICAL_ADMINISTRATION`. Track events per completed task and by category over pilot sessions. Desired trend: downward, particularly for Technical Administration and Configuration. A repeatable task that needs help after training is a UX/configuration defect, not merely user error.

## Success threshold for pilot expansion

No technical-administration assistance for normal tasks; no terminology confusion caused by VMOS/specialty leakage; no blocked data integrity step; and a documented owner-approved workaround for every missing capability.
